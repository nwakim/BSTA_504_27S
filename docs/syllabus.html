Description

Welcome to BSTA 504! This course introduces the ideas, practices, and applications of health data science in the context of public health and biomedical sciences. It focuses on the programming and workflow skills that health data work depends on: the command line, version control, reproducible environments, relational databases and SQL, and Python. You’ll practice each skill on real and realistic health data, and use AI coding tools responsibly along the way.

Prerequisites: BSTA 513 (Categorical Data Analysis) or BSTA 526 (R Programming for Health Data Science)

Format: 10 weeks, two lessons per week (3 hours of class time per week). Each lesson pairs a short demonstration with hands-on work on a health dataset.

Course Learning Objectives

By the end of this course, you should be able to…

  1. Describe the data science life cycle and the main types of health data, and where each fits in a research workflow.
  2. Use the Unix command line to inspect large files, run scripts, and work on a remote computer.
  3. Manage and share code with Git and GitHub, including branches, pull requests, and code review.
  4. Build a project that someone else can rerun, using renv and Docker.
  5. Query relational health data with SQL, from both a database and R.
  6. Read, write, and run Python code for common data tasks, and combine R and Python in one Quarto report.
  7. Use AI coding tools to speed up work while checking their output and protecting private health information.

Final Project

In teams, you’ll build a small analysis of public health data that someone else can rerun from scratch. The project must:

  • Live in a GitHub repository with a README, a clear folder structure, and a history of commits from every team member
  • Lock its R packages with renv and run inside a Docker container
  • Get its data with SQL, Python, or both
  • Report results in a Quarto document
  • Document any AI tools used and how their output was checked

In week 10, each team reruns another team’s project from GitHub and reports what worked and what didn’t.

Week 1 Setup Assignment

This is the first assignment of the course. It also shows how assignments are set up and submitted.

Due April 04 (end of week 1). Apply for GitHub Education at or before the first lesson, because approval can take several days.

Accounts

  1. Create a GitHub account (or use an existing one) with a professional username, and add your school email.
  2. Apply for GitHub Education with your school email and proof of enrollment.
  3. Once approved, activate Copilot Student from your GitHub Education benefits page.

Software

  1. Install R, Positron or RStudio, Quarto, and Git.
  2. Install Python with uv or Miniforge.
  3. Confirm your laptop can run Docker Desktop (Windows 10/11 or a recent macOS). Don’t install it until week 4.

Connect and test

  1. Connect Git to GitHub from R with usethis::use_git_config(), usethis::create_github_token(), and gitcreds::gitcreds_set().
  2. Run usethis::git_sitrep() and check that it reports no problems.
  3. Launch a GitHub Codespace, open its terminal, and run ls.

Submit

  • Your GitHub username
  • A screenshot of your GitHub Education approval (or pending status)
  • The output of usethis::git_sitrep()
  • Your operating system
  • Any step that didn’t work

Course Policies

Use of AI Tools

AI coding tools are allowed, and we’ll learn to use them well in week 9. When you use them:

  • You’re responsible for every line. Check all AI-generated code and its output before you submit it.
  • Say what you used. Note in each assignment which tools you used and for what.
  • Protect private health information.

Never allowed

  • Entering protected health information into a public AI tool
